# 0.6.6 分步骤模型与执行档案

本版本为写作与画图 V2 增加可冻结、可审计的逐 Step 执行配置。

- “调度设置与提示词 → 写作步骤/画图步骤”可配置阶段默认模型、推理强度和 Token 上限。
- 每个 Step 可继承阶段默认值，也可选择“质量优先、均衡、节省”档案或直接填写模型字符串。
- 模型下拉候选由当前隔离 Codex 账号动态读取，不把账号可用模型写死在程序中。
- 模型或推理强度不可用时，在创建 Turn 前阻塞并显示原因；不会静默回退到其他模型。
- 一篇论文仍只绑定一个固定 SDK 会话；不同 Step 通过同一会话的逐 Turn 参数切换模型，不增加会话数量。
- 论文进入阶段时冻结工作流与执行配置；运行中修改设置只影响之后进入该阶段的任务。
- 同一 Step 的重试继续使用原模型和推理强度；画图缓存指纹包含执行配置，换模型后不会误用旧缓存。
- 写作和画图实时任务表显示当前 Step、模型、推理强度、Token 上限/用量、固定会话 ID 和 Turn ID。
- 写作沿用既有分步 Token 硬上限；画图也支持可选硬上限并在 SDK 流式用量超过时请求中断。
- 没有修改写作、画图、选刊作者或投稿阶段的内部 Prompt 正文。
