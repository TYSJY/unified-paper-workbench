# Unified Paper Orchestrator 0.10.11

## 智能投稿一键检查

- “立即检查投稿状态”现在使用一个临时 Codex SDK 会话批量、只读搜索 Gmail，并要求每篇论文独立落账后才报告成功。
- 增加受限的 Gmail 只读搜索工具；监控不能发送、删除、标记或修改邮件，也不能依赖浏览器碰巧停留的页面。
- 自动从本地投稿包、状态与历史证据恢复稿件编号，避免为没有真实投稿证据的论文浪费检查 Turn。
- UI 显示检查总数、成功、失败、遗漏、动作类型、邮件摘要、批量会话与后续编排状态。

## 检查后的自动处理

- 接收：记录为 accepted 并归档，不再启动在线 Worker。
- 明确退稿/转投：程序自动排队选刊作者 V2 SDK Step 2–3，排除旧期刊并归档旧投稿包；新包验收后重新预检并进入 Smart SDK。
- 技术、文件或元数据修复：保留原投稿编号，只在该投稿的修订/重投入口继续，禁止创建重复新投稿。
- 科学内容返修：进入明确的修订稿等待状态；在新修订稿不存在时禁止上传旧稿或自动重投。
- 所有动作使用邮件事实指纹去重，重复点击“立即检查”不会重复转投、重复修复或重复提交。

## 稳定性与效率

- 清理历史邮箱检查错误写入的 `final_submit_confirmed` 投影；真实稿件编号、回执与投稿历史不受影响。
- 一篇论文固定一个投稿工作流，程序负责队列、并发、幂等与阶段交接；AI 只处理邮件语义和网页语义。
- 真实 Gmail 回归：7/7 论文检查成功、失败 0、遗漏 0；单个批量 Turn 约 1.47 万 Token。
- 未修改写论文、画图、选刊作者阶段已调试的内部提示词。
