# 0.4.7 发布记录：写作启动与串行队列修复

0.4.7 修复 V1 写作页点击“新建论文任务”或“启动本阶段”后看似没有反应的问题。根因是只存在主调度器时，
一个已废弃且不存在的 Automation 别名仍被当作不可读故障；同时嵌套失败只写入状态文件，没有显示在界面上。

## 修复

- 只要经过官方验证的主写作 Automation 存在且状态可读，不存在的旧别名不再阻止写作启动。
- 新建任务和阶段启动改为后台执行，界面立即显示忙碌状态，完成后明确弹出成功或失败原因。
- 成功提示说明调度器按心跳处理，并非点击后在当前窗口同步生成论文。
- 已处于自动运行状态时再次启动写作阶段按幂等成功处理。
- 多选“继续写作”改为一次性写入全部命令，再启动一次调度器，避免只排入第一篇。

## 写作并发边界

V1 写作调度器的阶段内并发固定为 1。它允许同时排队多篇论文，但每次只推进一篇论文的一个步骤。画图、
选刊作者等不同阶段仍可按高级入口并行运行。界面会显示这一真实边界，不提供没有实际执行效果的写作并发开关。

真正可配置的阶段内写作并发需要独立的事务型执行器、论文级任务认领和崩溃恢复；不能只增加一个数字设置。
该方向可以在不改动现有内部 Prompt 文件的前提下作为新的执行后端开发，但在完成官方可见线程续跑能力验证前，
继续保持并发 1。

## 验证

- 已在真实本机状态上完成“启动写作阶段 → 暂停写作阶段”无论文创建烟雾测试。
- 写作主 Automation 成功进入 ACTIVE，随后恢复 PAUSED。
- 20 份用户调优内部 Prompt 未修改。
