# Unified Paper Orchestrator UI 设计系统与信息架构

日期：2026-07-20  
适用基线：0.10.24 及后续版本

## 1. 目标与边界

本轮 UI 改造的目标是把控制台从“能看全量技术状态的工程后台”提升为“能长期日常使用的专业工作台”。设计优先级依次为：

1. 用户一眼知道当前状态、卡点、下一步和作用对象；
2. 主流程操作始终可见，低频和技术操作按需展开；
3. 1024×720 笔记本窗口仍能同时看到任务、论文列表和详情；
4. 大量论文下刷新、搜索和切换页面保持稳定；
5. 五个阶段共享同一套视觉语言和交互规则。

本轮不修改业务状态机、SDK 调度规则、内部提示词、产物契约或任务数据。UI 是现有权威状态的读模型与操作入口，不另建事实源。

## 2. 全局信息架构

主导航固定对应完整论文生命周期：

`总览 → 写论文 → 图表与插图 → 选刊与作者 → 投稿中心`

每个阶段页遵循同一阅读顺序：

1. 任务操作；
2. 当前执行摘要；
3. 全部论文；
4. 当前论文结构化详情；
5. 可选技术信息。

总览用于跨阶段判断，阶段页用于处理当前阶段，投稿中心用于长期投稿状态与人工接管。阶段之间不复制业务数据，只显示统一投影或各阶段权威运行账本。

## 3. 操作层级

每个页面只允许一个视觉主动作：

- 蓝色主按钮：对选中论文执行最常见的下一步；
- 普通按钮：上下文相关且安全的次要动作；
- “运行与暂停”：收纳阶段级批量启动、暂停；
- “更多操作”：归档、删除、越级、重跑、打开产物和诊断入口；
- 红色按钮：全局紧急停止等高风险操作。

选择型动作在没有选择论文时必须禁用，并在操作区直接说明禁用原因和作用范围。按钮名称必须说明对象，例如“运行选中画图”，不能使用含义不明的“启动本阶段”。

智能投稿的上下文按钮由当前论文状态动态切换为：

- 修改完成并继续；
- 转投其他期刊；
- 人工修改当前页面；
- 当前无需人工操作（禁用）。

## 4. 默认层与技术层

默认层只显示：

- 当前状态；
- 当前 Step / 进度；
- 下一动作；
- 卡点及责任方；
- 目标期刊、账号状态或必要产物；
- 最近事件。

技术层通过“技术信息”“技术日志”“显示模型与会话”“显示执行器与队列”等开关进入，包含：

- SDK 会话、Turn ID；
- 模型、推理强度和 Token；
- 执行器、队列、指纹；
- 原始状态和审计日志。

技术信息不得与用户下一步混在同一段原始文本中。

## 5. 状态视觉语义

普通、就绪和已完成项目保持白色背景，避免整页状态底色造成视觉噪声。

- 蓝色：运行中、选中、主动作；
- 绿色：成功或完成的 Badge / 文字；
- 黄色：等待人工、需要注意；
- 红色：阻塞或失败；
- 紫色：人工越级等特殊状态；
- 灰色：未开始、历史、不可用和技术辅助信息。

整行浅色背景只用于阻塞、失败、排队和人工越级等需要快速发现的状态。常态通过 Badge、文字或前景色表达。

## 6. 共享视觉令牌

实现位置：`unified_paper_orchestrator/ui/theme.py`

- 默认字体：Segoe UI 10 pt；
- 辅助字体：9 pt；
- 等宽技术字体：10 pt；
- 表格行高：33 px；
- 标准卡片：浅边框、白底、克制圆角感；
- 主色：企业蓝；
- 正常状态不大面积染色；
- 操作区、卡片、表格和详情使用统一间距。

新增页面必须复用主题样式和共享组件，不在业务页面内继续散落硬编码颜色、字体和状态样式。

### 6.1 品牌与图标资产

- 品牌标识与 Windows 应用图标位于 `unified_paper_orchestrator/ui/assets/`；
- 窗口标题栏、任务栏、EXE 文件和应用页头使用同一品牌标识；
- 阶段导航、主动作、指标卡片和空状态使用 `UIIconLibrary` 的同一线宽与语义色；
- 业务页面不得使用 emoji、系统字体图标或来源不明的网络图片充当永久图标；
- 位图品牌资产必须提供透明背景和多尺寸资源，并纳入 PyInstaller 与自动化资产契约测试。

## 7. 共享组件

实现位置：`unified_paper_orchestrator/ui/detail_panel.py`

### MetricStrip

用于总览和投稿状态概览。支持普通与紧凑模式，并按可用宽度自动调整列数：

- 920 px 及以上：同一行展示全部卡片；
- 600–919 px：最多三列；
- 600 px 以下：最多两列。

### StructuredDetailPanel

统一论文详情结构：标题、状态 Badge、关键结论、分组字段、卡点、最近事件和可选技术日志。标题允许自动换行，窄侧栏不截断论文编号。

## 8. 响应式与空间分配

- 全局头部在 900 px 以下自动换行；
- 阶段操作区在 860 px 以下自动换行；
- 1024×720 下，阶段“当前执行任务”默认折叠为摘要，可手动展开；
- 智能投稿运行 KPI 在低高度窗口默认折叠，可手动展开；
- 主表和详情面板始终占据剩余空间；
- 表格详情使用可拖动分栏；
- 当前任务不重复展示已经完成的历史任务，历史仍保留在全部论文和技术记录中。

原则：先保证用户看得到主任务表和下一步，再展示统计卡片和技术信息。

## 9. 性能规则

- 搜索输入使用 160 ms 防抖；
- 阶段内筛选只重绘当前阶段，不刷新所有页面；
- Treeview 使用增量同步，避免每次刷新全部删除重建；
- 结构化详情根据渲染签名跳过无变化重绘；
- 后台刷新不得阻塞 Tk 主线程；
- 自动刷新必须保留当前选择、滚动位置和详情上下文。

任何新增 UI 功能都应先复用现有投影和事件，不得为了显示方便重复扫描大量文件或创建第二套状态。

## 10. 页面约束

### 总览

显示跨阶段 KPI、搜索与状态筛选、全局论文表和结构化详情。技术信息默认关闭。

### 写作、画图、选刊作者

显示阶段主动作、可折叠当前任务、可筛选全部论文和阶段详情。模型、会话和 Token 属于高级层。

### 投稿中心

默认优先显示任务列表和结构化状态；运行概览在小屏折叠。右侧详情按“状态—下一步—卡点—目标期刊—账号—最近事件”组织，原始日志默认隐藏。

## 11. 测试与发布门槛

每次 UI 发布至少验证：

1. UI Python 编译；
2. UI 安全、写作、画图、选刊作者和 V1 兼容契约测试；
3. 全仓测试；
4. 1024×720 实际 EXE 的五页视觉检查；
5. 主按钮禁用/启用、搜索、防抖、详情和高级层切换；
6. 未触发真实投稿、删除或阶段执行的只读验收。
