# Qt Quick 工作台架构（2026-07-22）

## 目标与边界

0.11.0 完成桌面呈现层迁移；0.11.1 起 Qt Quick 是唯一正式桌面壳层。写作、图表、选刊作者和 Smart Submission 的状态机、SDK 固定会话、提示词、产物契约、账号库和文件目录仍由既有 Python 模块负责。旧稳定投稿只保留历史状态读取，不再拥有产品执行入口。

## 分层

1. `ui_next/qml/`：Qt Quick 纯呈现层。包含品牌头部、阶段导航、操作栏、指标卡、虚拟化论文列表、详情侧栏、确认框和数量选择框。
2. `ui_next/models.py`：`QAbstractListModel` 读模型。只在内存中搜索、筛选和切换阶段，不重新扫描磁盘。
3. `ui_next/i18n.py` + `ui_next/locales/`：统一处理 QML 与 Python 读模型的运行时语言切换、回退和持久化。
4. `ui_next/read_model.py`：把历史上不完全一致的状态字段投影为本地化状态、颜色、进度和下一动作。它不回写业务状态。
5. `ui_next/controller.py`：QML 与既有应用服务之间的适配器。所有耗时刷新和启动/暂停操作进入线程池，主界面线程不执行目录扫描或阶段同步。
6. 既有 `UnifiedOrchestrator`、各阶段 SDK runtime、全流程 runtime 和 Smart Submission：继续拥有真实任务、队列与副作用。

## 启动与刷新

- 双击 EXE 后先读取 `unified_state.json` 缓存并立即绘制首屏。
- 窗口显示后再执行一次后台 `sync(persist=True)`；刷新期间已有内容保持可操作。
- 搜索和状态筛选只操作内存模型，并带 170 ms 防抖。
- 论文列表使用 Qt Quick `ListView` 的项目复用，不再为全部论文持续创建控件。
- 同一时刻只允许一个后台 UI 操作；刷新请求会合并，避免重复扫描。

## 操作归属

- “运行全部 / 安全暂停 / 新建写作 / 一键全流程”调用原有应用服务，不复制调度逻辑。
- 影响整个阶段的操作在 UI 中明确写为阶段队列操作，并显示确认框。
- 投稿页的“启动智能投稿”确定性扫描合格论文、完成 Smart 路线准备并启动程序控制的 SDK 队列，不调用旧稳定投稿阶段启动器。
- 正式产品不存在“经典控制台”或 `ui-legacy`；Qt 初始化异常时明确报错并退出，防止无意进入另一套行为不同的界面。
- “账号与站点”作为独立业务窗口保留，它不是旧控制台入口。

## 响应式与视觉系统

- 默认尺寸 1540×900，最小尺寸 1080×680。
- 宽屏显示固定详情侧栏；窄屏将详情放入抽屉，避免主表被压缩到不可读。
- 颜色只表达状态：正常行保持白色，选中行使用浅蓝，验收/人工项使用橙色，真正阻塞才使用红色。
- 技术信息默认折叠；SDK 会话、原始状态和 JSON 只在用户主动展开时显示。
- 字体、圆角、边框、阴影、动画时长和 Fluent 字体图标统一由 `Theme.qml` 与组件库管理。

## 发布与回退

- PySide6 Essentials 被固定到 6.11.1；QML 源码作为打包数据进入同一个 EXE。
- QML 与 Python 共用的 JSON 语言目录作为打包数据进入同一个 EXE。
- PyInstaller 明确排除经典 `ui.main_window`；产品只保留现代入口与独立账号站点业务窗口。
- 0.11.0 正式 EXE 与切割前源码已单独备份；需要恢复时回退完整版本，不在新版内部混用旧壳层。

## 后续迁移原则

账号与站点等低频复杂配置当前以独立业务窗口运行。后续按“真实使用频率—错误率—维护成本”排序迁入 Qt，不在 QML 中复制业务逻辑；每迁移一个窗口，都先抽成无 UI 的应用服务，再为 Qt 增加薄适配器。
