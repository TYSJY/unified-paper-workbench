# 0.5.9 写作任务实时进度与单会话调度

## 界面与操作语义

- 写论文页新增 SDK 实时任务表，尚未完成 Step 1、还没有论文编号的任务也会立即出现。
- 每个任务直接显示实时状态、当前 Step、十格总进度、等待/卡点和最后更新时间；界面每 2 秒读取本地状态自动刷新。
- “运行全部写作任务”明确作用于整个写作队列；“暂停全部写作（当前 Step 后）”不会强制中断正在执行的 Step。
- “继续选中论文”和两条 Step 5→6 数据放行路径只运行当前明确选择的论文，不会顺带恢复旧队列。
- 新建对话框明确区分“本次新建数量”和“全局写作并发上限”。
- Step 5→6 的实验数据门禁在实时表中显示为用户可执行的说明，手动确认路径不修改论文正文。

## 调度修复

- 每篇论文只占一个固定 Codex SDK 根会话，Step 1→10 在该会话内顺序执行；禁用 Codex 多代理功能，不再为每篇论文预留 3 个子会话。
- 新建论文时写入唯一请求标识，连续两次新建一篇论文不会再被去重为同一个 pending 命令。
- 新任务到达旧调度批次后，已发送的 Step 正常完成；旧任务在下一个 Step 边界让出，随后只运行本次新建的精确任务集合。旧队列只有点击“运行全部写作任务”才会恢复。
- 调度优先级只改变并发槽进入顺序，不改写用户 Prompt，也不取消已发送的 Codex 回合。

## 状态来源

- 实时执行状态以 `state/writing_sdk_dispatch.json` 的 SDK journal 为事实源。
- 尚未注册到 journal 的新任务由写作 pipeline 中的 pending command 补充显示。
- 论文文件只由既有步骤验收器用于确认产物完成，不再由 UI 猜测“当前正在执行哪一步”。

## 兼容性

- 唯一用户入口仍为 `dist/UnifiedPaperOrchestrator.exe`。
- 20 份用户调优内部 Prompt 保持原字节不变。
- 画图、选刊作者和投稿阶段的内部 Prompt 与既有执行逻辑未修改。
