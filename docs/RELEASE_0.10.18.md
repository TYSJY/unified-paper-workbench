# Unified Paper Orchestrator 0.10.18

## 重点变化

- 智能投稿的调度权统一交给本机程序：程序判断队列、并发槽、每日检查是否到期和任务认领；Codex SDK 只执行单篇论文已经确定的受限网页任务。
- “启动智能投稿”、恢复登录、队列优先和自动后续任务直接启动 SDK 运行时，不再先唤醒一个 Codex Automation 调度会话。
- 每日状态检查统一使用 Windows 定时任务 `UnifiedPaperOrchestrator-SmartSubmission-Monitor`，命令为 `smart-submission-program-tick`；控制台打开时使用同一份跨进程锁和每日认领账本防漏，两个入口不会重复执行同一天的定时检查。
- 历史 Codex Automation 不删除、不改写原提示词，仅强制切换为 `PAUSED` 并作为回退审计记录保留。
- 智能投稿界面明确显示程序定时器、触发时间、本机任务注册状态、SDK 队列和固定会话；历史 Automation 移入“历史回退说明”，不再显示“旧调度器：运行中”。
- 保留旧命令名作为兼容别名，但新安装与迁移只注册程序命令，避免旧 EXE、旧 Automation 和新版窗口三路重复唤醒。

## 兼容、回退与数据

- 变更前已备份 Automation 配置、Windows 定时任务信息、Smart 状态和 SDK 派发状态；回退时可恢复旧 TOML 与旧任务命令。
- 既有投稿队列、论文状态、固定 SDK 会话和监控记录不迁移、不重置，也不会因调度器切换而自动重投。
- 没有修改写作、画图、选刊作者阶段及其内部提示词，也没有增加新的业务拦截规则。

## 验证

- 覆盖程序定时任务注册、旧 Automation 只暂停不改提示词、API 模式直接启动 SDK、硬暂停保持队列、跨入口单一所有权和 UI 调度契约。
- 发布构建执行完整隔离测试、版本探测、SDK/CLI 依赖探测以及打包命令行烟雾测试。
