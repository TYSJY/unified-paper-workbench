# Unified Paper Orchestrator 0.10.5

本版本修复智能投稿“首次启动”与“已有任务续跑”共用入口时的状态识别错误。

## 修复内容

- Review 页已经验收完成、状态为 `waiting` 且只等待自动最终提交的论文，现在可由“启动智能投稿”直接续跑。
- 续跑不会重新导入论文，不会旋转 `attempt_id`，不会替换 `next_action`，也不会丢失原固定 Codex SDK 会话。
- 已经签发但尚未执行的精确最终提交权限，也可以重新加入 SDK 运行范围；仍沿用一次性、防重复提交规则。
- 自动最终提交被关闭时，Review-ready 任务不会被误启动，而是明确提示使用手动最终确认入口。
- 启动失败弹窗现在列出所选论文对应的实际跳过原因，不再只显示笼统的“预检未通过”。

## 验证

- 新增 Review-ready 续跑回归，确认状态、投稿尝试、固定 SDK 会话和最终审核动作均保持不变。
- 智能投稿程序、SDK 运行时、最终提交门禁和 UI 的 80 项相关测试通过。
- 完整发布测试通过：1055 项测试、54 项子测试；PyInstaller 与发布版 CLI 烟雾验证通过。

## 不变边界

- 写作、画图和选刊作者阶段的内部提示词未改动。
- 本次验证不会触发真实论文的最终提交；用户在新版中再次点击“启动智能投稿”后，任务才进入自动提交链路。
