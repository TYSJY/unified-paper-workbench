# 0.7.0 选刊作者可配置流程与零 Token 验收

本版本把“选刊与作者”补齐为与写作、画图一致的 V2 可观察、可配置阶段，同时继续由程序负责调度，不引入 AI 调度器。

- 保留默认“合并模式”：每篇论文在一个固定 SDK 会话中只发送一次既有 `02_03_choose_journal_and_make_package.md`。
- 新增“精细模式”：在同一固定会话依次执行既有 Step 2 选刊、程序本地门禁、既有 Step 3 投稿包；只有选刊结果为 `Recommended` 才自动继续。
- 工作流在论文入队时冻结，可追加、删除和排序末尾自定义步骤；内置交付链受保护。阶段默认值和每个 Step 均可独立配置模型、推理强度与 Token 上限。
- 新增“只重新选刊”和“只重新生成投稿包”，避免一个局部问题导致整段流程重复调用 AI。
- 新增“仅重新验收（不调用 AI）”，直接检查当前 `journal.md`、投稿包、编译 PDF、残留标记和元数据指纹，模型 Token 消耗为 0。
- 元数据指纹现在包含作者、声明、选刊偏好和工作目录输入哈希；输入未变化时保持文件字节稳定，不会因重复点击而让有效投稿包失效。
- 新增每篇论文选刊偏好表单：分区、OA/APC、最低收录、关键词、优先/排除期刊和稳中稿策略会写入 `journal_preferences.md`。
- UI 新增打开 `journal.md`、`main.pdf`、投稿包目录以及阶段专用右键操作；实时任务表按冻结流程显示当前 Step、模型、Token、会话和门禁原因。
- 阶段交接区分“AI 流程完成”和“可直接投稿”：只有 `READY_TO_SUBMIT` 自动进入投稿；`NEEDS_MINOR_FIX` 保留在选刊作者阶段等待人工处理。

本版本没有改写写论文、画图、选刊作者或投稿阶段的任何内置提示词。选刊作者调度器及四份任务提示词继续通过固定 SHA-256 校验确认字节未变。
