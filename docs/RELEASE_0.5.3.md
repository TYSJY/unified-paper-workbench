# 0.5.3 发布记录：写作门禁与产物验收加固

## 核心变化

- 本地确定性调度器继续保持“每篇论文一个固定 Codex 会话、论文内 Step 1–10 顺序执行、论文间并发”的结构，不再引入模型调度器。
- Step 3 绑定选题卡与四个 Step 2 参考文献文件的稳定字节快照；Step 6 绑定草稿、材料说明、验证清单以及清单声明的全部动态证据文件。
- 容量等待后、发送前和回合完成时都会重新验证门禁快照。即使替换后的文件仍然通过业务门禁，只要不是本回合授权的字节版本，就不会提交该回合。
- Step 2 合法元数据修正无需重跑模型回合，但必须保留完成时产物指纹、当前指纹、门禁快照和修订历史；旧的终态协调器不再静默覆盖同一步产物指纹。
- Step 3–10 的主要产物增加语义合同验收，合同仅实现既有 Prompt 已明确要求的章节、参考文献、图表、验证块和审稿结构，不改变 Prompt。
- Step 3/6 前置条件不足时进入可恢复的 `waiting_prerequisite`，条件满足后重新运行即可继续；语义不合格产物只允许经过显式、留痕的安全重排。
- 临时单篇金丝雀运行使用 digest/provenance lease 恢复活动论文，不覆盖并发选择；成功步骤通过 source-aware 投影协调器同步统一状态。

## 不变项

- 不修改写论文、画图、选刊作者和投稿的任何用户调优内部 Prompt。
- 不覆盖 Codex Desktop 的登录、配置或任务；写作 SDK 继续使用 `state/codex_sdk_home`。
- 不启用旧写作 Automation，不处理旧投稿通道。

## 验收策略

- 先用发布版 EXE 对现有固定会话执行单篇、单步骤金丝雀，验证产物、门禁、状态投影与 Token 审计。
- Step 5 生成的模拟验证块必须等待真实证据导入并通过 Evidence v2 门禁，不能为了跑完整流程而伪造实验结果。
- 单篇通过后再恢复其余任务；全局主会话和可检测子会话仍共同受 10 会话容量上限约束。
