# Unified Paper Orchestrator 0.10.21

本版修复智能转投建单后的界面报错与选刊作者 SDK 恢复链路，不修改写作、画图、选刊作者阶段内部提示词。

## 修复内容

- “转投其他期刊”后台操作完成后改用控制台现有的统一刷新接口，不再调用不存在的 `refresh_all`。
- 选刊作者调度计划正式接受 `retarget` 模式，并继续使用拆分的原 Step 2（重新选刊）和 Step 3（重建投稿包）。
- 兼容新版 Codex SDK 的 `ThreadItem(root=...)` 数据结构，以及 `Turn.run()` 仅返回空壳、完整内容稍后出现在固定会话历史中的情况。
- 已误判为 `JOURNAL_AUTHOR_EMPTY_COMPLETED_TURN` 的任务可以沿用原 request ID、thread ID 和 turn ID 恢复；程序先验收原 Turn，不重复发送已经完成的选刊 Step。
- 只有可安全恢复的 SDK 技术故障会被选中恢复重新入队；期刊选择、作者资料和投稿包等业务门禁不会被绕过。
- SDK 后台线程异常会写入持久状态，任务继续留在队列并在界面显示具体原因，重启控制台后也不会静默丢失。
- 新增 ScholarOne Manuscripts 确定性站点适配器，允许程序把 JAISE 等 `mc.manuscriptcentral.com` 期刊绑定到正确投稿系统。
- 转投后的站点解析必须精确匹配当前目标期刊；旧期刊即使仍保留论文关联，也不能再成为路由回退项。当前目标没有可信站点时会停止，而不是投到历史站点。
- 新转投交接会清除旧投稿编号的来源投影，并禁止从兼容账本或旧投稿包重新激活历史/推测编号；旧编号只保留在投稿尝试历史中。
- 投稿包中“仅当在线系统要求时补充”的模板、结构化摘要和作者贡献项目由确定性契约归类为条件项，不再误阻塞已可提交的 LaTeX 投稿包。

## 验证重点

- `retarget` 拆分流程可以进入选刊与投稿包两个执行步。
- SDK 空壳结果能从固定会话历史恢复。
- 已阻塞的空 Turn 可在不重发选刊的情况下继续投稿包 Step。
- 智能转投完成回调使用存在的刷新 API。
- 新旧两个站点同时关联同一篇论文时，程序只选择当前目标期刊对应的 ScholarOne 站点。
- 新转投在真正获得投稿回执前保持空的新投稿身份，不会恢复旧稿件编号。
- 智能转投、选刊作者、界面安全和公共接口回归测试通过。
