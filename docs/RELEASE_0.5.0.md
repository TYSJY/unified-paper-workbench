# 0.5.0 发布记录：本地事件驱动写作

## 结果

写论文阶段已从“Codex Automation 定时唤醒模型调度器”切换为“EXE 内单一本地调度器直接驱动 Codex SDK”。旧写作 Automation 保留为兼容回退，但必须保持 `PAUSED`，不会再按分钟创建调度会话。

## 执行模型

- 一个本地确定性调度器管理全部论文和并发槽，本身不消耗模型 Token。
- 每篇新论文固定一个 SDK 会话，Step 1–10 每步一个 turn，逐步验收后继续。
- Step 1 串行，避免论文编号竞争；Step 2–10 可以跨论文并发。
- 全局预算上限为 10；默认按 Step 1=4、Step 2=4、其余步骤=1 预留主会话和潜在子会话容量。
- SDK 完成事件直接推进状态，没有分钟轮询。
- 暂停会立即切换为手动模式；当前步骤完成后，不再启动下一步。

## 账号与双模式

“AI执行与API”窗口保留两种用户可选模式：

- `Codex 账号模式（完整流程）`：在 EXE 中连接 ChatGPT 账号。SDK 使用 `state/codex_sdk_home`，不覆盖 Codex Desktop 登录。
- `API 密钥模式（当前仅审阅）`：继续支持通用 Responses 兼容配置、连接检测和 Prompt 07 私有暂存审阅；尚未接管完整四阶段流程。

账号未连接时，新建或启动写作严格不写入队列。登录、状态检测和错误输出均不打印密钥、令牌、授权 URL 或验证码。

## 现场迁移

发布时现场共有 8 篇明确请求的任务：

- 2 篇已由旧 Desktop 路径完成 Step 1，首次启动时从 Step 2 创建一个隔离 SDK 会话；旧线程号保存在 `legacy_thread_id`。
- 6 条待处理 `new_session` 命令从 Step 1 开始，并从第一步起固定 SDK 会话。

迁移计划只读验证为 8 条；发布过程未登录账号、未调用模型、未启动论文步骤。

## 不变项

- 写论文 10 份步骤 Prompt、写作调度 Prompt 以及画图、选刊作者、投稿内部 Prompt 均不改写。
- 旧投稿和智能投稿双通道不在本次迁移范围内。
- API 模式不会静默回退到 Codex 模式。

## 验证

- SDK dispatcher、live runtime、账号隔离、WritingAdapter、UI 与 CLI 均有离线测试。
- 所有用户调优写作 Prompt 已做 SHA-256 原字节复核。
- 打包前运行完整测试、Ruff、隔离构建探针和发布 EXE 版本/启动探针。

## 已知边界

- SDK 当前没有 `thread/start` 幂等键；创建结果不确定时会阻断并等待人工对账，不自动重复创建。
- 10 会话预算可覆盖本 EXE 及 SDK 可见子线程，但不同 Codex 进程之间没有官方原子全局 semaphore。用户同时在 Codex Desktop 启动其它任务时，仍需自行留出容量。
- EXE 进程退出时，后台运行会中断；私有 journal 会在下次启动时做防重复恢复，但正在发送边界无法证明时会 fail closed。
