# 0.8.0：独立论文工作区

本版本把“程序”和“论文项目数据”拆成两个清晰层次，同时继续只发布一个
`UnifiedPaperOrchestrator.exe`。

## 用户可见变化

- 主窗口顶部持续显示当前论文工作区名称、绝对目录和工作区类型。
- “论文工作区”窗口支持新建空白工作区、导入当前全部数据、添加已有工作区、
  切换工作区、打开目录和仅从列表移除。
- 切换工作区时，EXE 会先检查写作、画图、选刊作者和智能投稿是否仍有正在执行
  的 Turn；安全后保存选择并由同一个 EXE 重新打开。
- 命令行可使用 `--workspace <目录>` 临时指定工作区，也可使用
  `workspace-status`、`workspace-list`、`workspace-create` 和 `workspace-use`
  管理工作区。

## 工作区结构

```text
论文工作区/
├─ workspace.json
├─ state/
└─ stages/
   ├─ writing/
   ├─ figures/
   ├─ journal_author/
   └─ submission/
```

`workspace.json` 是唯一入口清单；四阶段根目录、统一状态、工作流快照、SDK
调度记录和智能投稿状态均由该清单解析，不再依赖写死的历史论文目录。

## 本次迁移

已建立默认主工作区：

```text
D:\PaperProjects\UnifiedPaper-Main
```

迁移采用复制而非移动：

- 旧论文目录和旧统一状态目录保持原样，没有删除；
- 过滤 Git 对象、构建产物、日志、锁文件、Chrome Profile、`node_modules`
  和历史迁移包等非业务体积；
- 写作、画图、选刊作者和投稿的活动状态在副本中统一暂停，防止切换后自动重复执行；
- 当前 JSON 状态中的历史绝对路径改写为新工作区路径；
- 写作 29 篇、画图 24 篇、选刊作者 23 篇的目录集合与来源逐项一致；
- 24 份阶段提示词复制前后逐字节一致。

导入审计保存在工作区的
`legacy_import/migration_manifest.json`。旧目录继续作为“旧版兼容工作区”保留，
因此回退不需要恢复或逆向迁移。

## 空白工作区

新建空白工作区不复制论文和历史队列，但会复制阶段提示词、兼容控制脚本、
作者模板及投稿工具等运行骨架，再生成空队列和手动暂停状态。这样新目录不仅
能被 EXE 识别，也能直接创建第一篇论文。

## 兼容性

- 写作、画图和选刊作者的内部提示词正文未因工作区功能而修改。
- 选刊作者与稳定投稿在运行时增加工作区路径绑定；提示词中的历史绝对路径仅作为
  相对后缀别名，不允许把新任务写回旧目录。
- 已有历史目录仍可通过工作区管理器显式切回。
