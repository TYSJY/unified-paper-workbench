# Unified Paper Orchestrator 0.10.4

本版本把智能投稿的授权边界调整为“启动即授权完整流程”：用户选择论文并点击“启动智能投稿”后，程序可以在最终审核通过时自动完成最终提交，不再要求逐篇进行第二次确认。

## 主要变化

- `settings.auto_final_submit_enabled` 默认启用，并自动应用到已有智能投稿工作区；设置页可明确关闭，以恢复逐篇手动确认的回退模式。
- SDK Worker 到达最终审核页后仍先返回统一的 Review-ready 标记，Python 程序随后签发短时、签名、一次性的精确尝试权限，并把同一篇论文重新派发到原固定 SDK 会话完成最终提交。
- 同一次 SDK 调度可以连续完成“审核 Turn → 自动授权 → 最终提交 Turn”，无需等待下一次人工操作或旧 AI 调度器轮询。
- 最终提交权限继续绑定论文、路线版本、投稿尝试、账号、投稿系统、期刊、目标域名、站点、远程草稿和本地投稿包指纹；普通浏览器点击工具无法绕过专用最终提交工具。
- 权限一旦被预留、领取、点击或出现结果不明，程序只核验远端结果，绝不再次点击。仅当权限从未预留、从未使用且已自然过期时，程序才回到已审核状态并安全签发新的精确权限。
- UI 默认隐藏逐篇“确认最终提交”入口，启动对话框明确说明会自动提交；关闭自动策略后仍可使用原人工确认流程。
- Smart 本地兼容账本继续保留全局 `submission.execute` 审批标记作为不可派发的审计记录；生产执行权限来自主状态中的签名一次性能力，不削弱全局 Workflow Kernel 的安全规则。

## 验证

- 自动最终授权、同论文双 Turn、并发调度、一次性绑定、UI 默认策略和过期未使用权限恢复的 79 项相关回归测试通过。
- 完整隔离测试通过：1054 项测试、54 项子测试；PyInstaller 打包以及发布版 CLI/版本烟雾验证全部通过。

## 不变边界

- 写作、画图和选刊作者阶段的内部提示词未改动。
- 密码仍由本机可信凭据代理直接填入受控浏览器，不进入 SDK Prompt、会话记录或任务日志。
- CAPTCHA、2FA、付款/强制 OA、强制 ORCID、邮箱验证以及缺失或不确定的法律、伦理和作者事实仍会形成可恢复卡点。
- 本次开发和构建不会自动点击真实论文的最终提交按钮；安装新版后重新启动对应智能投稿任务，才会按默认策略继续。
