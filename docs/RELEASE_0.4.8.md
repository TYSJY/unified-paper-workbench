# 0.4.8 发布记录：写论文真实并发

0.4.8 为 V1 写论文阶段增加真正的多论文并发。实现沿用旧画图调度器已经实机运行过的隔离方式：一个官方
Codex Desktop Automation 负责填充槽位，每篇论文由独立可见线程执行，并只写自己的 idea、refs 和 paper 目录。

## 用户功能

- 写论文页“调度设置与提示词”可以设置 1–4 个并发槽，当前本机默认配置为 2。
- “新建论文任务”可以选择一次创建几篇，数量不超过当前并发上限。
- 多选“继续写作”会一次性加入完整队列，由调度器填满空闲槽位。
- 写论文页状态栏显示“正在运行/并发上限”。
- Step 1 顺序创建，避免多个线程同时争用当天的论文编号；从 Step 2 开始可以真正并行。

## 防冲突与恢复

- 派发决策在本地锁内完成，每篇每一步先持久化 claim，再调用 Desktop 线程工具。
- claim 带随机令牌、精确 paper id、step、thread id、输入指纹和派发前 terminal 基线。
- 同一线程和同一论文不会同时拥有两次活动派发；重叠心跳只能看到已占用槽位。
- Desktop 调用前先进入 `send_uncertain`。调用或回写结果不明确时不自动重试，避免重复生成。
- 完成仅接受派发基线之后、论文 ID 和步骤精确匹配、预期产物可指纹验证的 terminal。
- Step 3 新颖性门和 Step 6 证据门仍在 claim 前执行；失败只暂停对应论文，不再暂停整个并发队列。
- 降低并发上限会撤销尚未发送的多余 reservation，已经发送或运行的任务自然排空。
- 暂停调度器不会声称取消正在运行的 Codex 线程，只阻止新的 claim。

## Prompt 边界

20 份用户调优内部步骤 Prompt 原字节不变，外部 `controller/SCHEDULER_PROMPT.md` 也不修改。并发 sidecar
只读提取其中已有的 Exact Step 模板并替换论文 ID；代码生成的控制信封只禁止 worker 修改共享状态。

## 验证范围

- 两个并发 prepare 在并发上限 2 时总共只能认领两篇，不能认领第三篇。
- 同一批已认领任务在下一轮不会重复派发。
- Step 1 即使上限为 4 也只创建一个新线程；下一轮可同时派发下一篇 Step 1 与已创建论文的后续步骤。
- 防重令牌、过期 reservation、暂停竞态、并发上限降低、精确 terminal 对账和 prompt 文件不变均有自动测试。
