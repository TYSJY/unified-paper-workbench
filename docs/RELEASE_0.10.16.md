# Unified Paper Orchestrator 0.10.16

## 重点变化

- 智能投稿的“立即检查投稿状态”和定时巡检从 Gmail 单来源升级为学校邮箱、Gmail、期刊后台三层检查。
- 程序从统一账号库自动发现并去重可自动使用的学校邮箱记录；凭据仅由本机连接器读取，不进入 Codex SDK 提示词、状态文件或审计。
- 学校邮箱按一次巡检批量扫描最近 120 封邮件，先由程序按投稿编号或完整标题精确匹配，再把限定的主题、短摘要、日期和发件域名交给 SDK 做通知语义分类。
- Gmail 继续使用受限的只读批量搜索，不允许发送、回复、转发、删除、归档、下载附件或跳转邮件外链接。
- SDK 必须为每篇论文返回所有已配置来源；缺少任一来源时整批失败，避免部分结果被误当成完整检查。
- Python 确定性聚合逐来源结果。明确接收、拒稿或返修才触发后续处理；无明确通知或来源冲突时自动核对期刊后台。
- 邮箱到期刊后台的回退使用新尝试编号和原论文固定 SDK 会话；回退无法排队时落账为“检查失败”，不会显示成正常。
- 智能投稿详情页逐来源显示“已检查/不可用”、状态、短摘要或错误码；检查中会区分“多邮箱”和“期刊后台”。
- 写作、画图、选刊作者阶段以及各阶段内部提示词均未修改。

## 数据边界

- 账号、密码、Cookie、完整发件地址和完整邮件正文不会进入 SDK。
- 状态账本仅保存脱敏后的来源标识、可用性、分类结果、短摘要、日期、发件域名、投稿编号和错误码。
- 邮箱连接器为只读；期刊后台回退仍遵守既有投稿状态机和固定会话约束。
