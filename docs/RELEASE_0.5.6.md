# 0.5.6 发布记录：写作文献门禁兼容性修复

## 真实运行发现

两篇论文以固定 Codex SDK 会话真实并发运行时，论文 `2026-07-13_002_adaptive-npu-rendezvous` 完成了 Prompt 02 要求的四份产物，其中 `references.md` 使用规范的 `R01`–`R52` 表格行号。旧解析器只接受纯数字首列，因此将 52 条可验证参考文献误判为 0 条。

## 修复

- 保留原有 ASCII 纯数字表格行号的兼容性。
- 增加对有界、全匹配的规范 `R01`–`R09`、`R10+` 行号的支持。
- 拒绝 `R00`、模糊后缀、Unicode/全角数字以及过长数值，避免把表头或异常内容计为文献记录。
- 不改动写作、画图、选刊作者和投稿的任何内部 Prompt。
- 不改动已生成的论文或文献产物，不为此重跑模型。

## 真实数据验收

修复后直接对原产物执行只读门禁：

- `reference_count = 52`
- `verified_reference_count = 52`
- `bib_entry_count = 52`
- `identity_match_count = 52`
- `status = READY`
- `issues = []`

这证明原产出本身合格，阻塞由校验器格式兼容性造成，不需要消耗额外 Token 返工。
